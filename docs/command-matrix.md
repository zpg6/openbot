# Core command matrix

This matrix is the design contract for core mutations. It does not mean every route or store exists. The current application registers a health route and a dependency-injected local browser proof for Bot creation and one synthetic read-only run; that proof does not implement the production authentication, idempotency, audit, outbox, D1, or provider contracts below.

All browser actions and unsafe `/api/v1` routes require an authenticated session, fixed `Origin`, CSRF token, account membership, and a random idempotency key. A key is scoped to account, actor, command kind, target, and canonical command digest. Repeating the same key and digest returns the stored response reference. Reusing the key with another digest returns `409 idempotency_mismatch`.

Browser success uses `303` to the fixed route shown by the use case. API create success uses `201`, other API mutation success uses `200`, and content deletion uses `204`. A stale expected version returns `409` with the listed stable code. Cross-account targets return `404` before version details.

## Effects outside the request

An outbox row names one typed effect and immutable target reference. A user-facing command never performs a blind external retry. The consumer claims by outbox ID, records a provisioning or cleanup intent before the vendor call, and treats an ambiguous response as reconciliation work.

Catalog, grant, connection, confirmation, and run commands append their redacted audit event in the same control-store transaction as the authority change. Better Auth mutations must use the same application audit operation or a transactionally linked local event before item 2 closes.

## Commands that do not exist

There is no command for provider business-data writes, arbitrary MCP registration, shell access, package installation, port exposure, persistent Sandbox storage, artifact upload, Bot handoff, schedules, teams, or owner-marked cleanup completion. The server returns the matching stable deferral code and performs no side effect.
